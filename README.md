# TapReplay

Android 端末の画面操作を **記録して再生する** 汎用ツール。PC に映した端末画面の上でボタンをクリックしていくだけで手順を作成でき、あとはそれを好きな回数くり返し再生できます。座標のベタ書きが不要で、画像マッチングでボタンを探すため、多少の待ち時間のばらつきにも耐えます。

想定用途：アプリの動作確認・回帰テスト（QA）、社内の定型作業の自動化（RPA）、繰り返し操作の補助など。

## 特長

- **記録は画面をクリックするだけ** — PC に端末画面を表示し、その上でボタンを順にクリック。座標変換やテンプレート画像の手切り抜きは不要
- **動きのある画面でも安定して検出** — 記録時に同じ場所を数フレーム撮って、その間ずっと変化しなかった部分だけでボタンを判定。半透明ボタンや背景がアニメーションしている画面でも、まわりの変化に惑わされずに検出できる（見つからない場合は輪郭ベースの判定に自動で切り替え）。要素IDが取れないアプリ（Unity 製など）でも動く
- **待ち時間のばらつきに強い** — 「その画像が現れるまで待つ」方式なので、固定 sleep のようにズレて崩れない
- **共通ポップアップに対応** — 広告や「フレンド申請」など、決まった順番に関係なく割り込んでくる画面を登録しておける。再生中はどのステップを待っていても検知して自動で閉じる
- **止まった続きから記録を追加できる** — 途中で操作が変わっても、同じレシピ名で記録開始すれば続きから追加できる
- **よく止まる箇所が分かる** — 失敗のたびに日時・原因・スクリーンショットを記録し、失敗回数の多いステップをランキング表示
- **各設定に「?」マーク付き** — 設定名や機能名の横の丸い「?」をクリックすると使い方が表示される
- **GUI 付き** — 記録／再生／停止、実行回数、ログ表示。放置実行の状況が見える

## 動作要件

- Windows（macOS/Linux でも Python 環境があれば動作）
- Python 3.11〜3.13（`requirements.txt` の numpy が 3.11 以上を要求。3.14 は opencv-python / PySide6 / adbutils / PyInstaller のビルド済み wheel がまだ提供されておらず非対応）
- Android 端末（USB デバッグ ON）
- platform-tools（`adb`）

## セットアップ

```bash
pip install -r requirements.txt
```

- 端末：設定 → 開発者オプション → USB デバッグ を ON
- `adb devices` で端末が表示されることを確認（初回は端末側にエージェントが自動導入される）

## 使い方

`dist\TapReplay\TapReplay.exe` をダブルクリックして起動します（未ビルドの場合は先に「exe にする」を参照）。

1. **接続** — USB 接続して「接続」。モデル名と画面サイズが出れば OK
2. **記録**（記録タブ） — レシピ名を入れて「記録開始」。PC に端末画面が出るので、操作したいボタンを実行したい順にクリック → 「保存して閉じる」
   - クリックは端末にも送られて画面が進む
   - 1回のクリックにつき同じ場所を数フレーム撮影して判定用の画像を作るため、クリック直後は数秒待ちになります（固まったわけではありません）
   - 画面が進むのを待ちたいときは「画面更新」で最新画面にしてからクリック
   - 間違えたら「一つ戻す」
   - 記録済みのステップは一覧からダブルクリックで名前を変更できる
   - 「共通ポップアップとして記録」にチェックを入れてクリックすると、広告や「フレンド申請」など不定期に割り込む画面のボタンを、順番を問わず閉じる対象として登録できる
   - 既に記録済みのレシピ名を指定すると、続きから追加記録するか選べる
3. **再生**（再生タブ） — 実行回数（0 = 無限ループ）を入れて「再生開始」
   - 対象のボタンが見つからないとき、直後2ステップ以内に別のステップの画像が写っていないか自動で探し、見つかればそこまで進めて再生を続けます（想定外の画面が挟まっても手順が止まりにくくなります）
   - ただしこの機能で進んだ回は、全ステップを順番通り実行できた保証が無いため「成功」ではなく「不完全」として別に集計されます
4. 止めるときは「停止」
5. **記録内容／失敗履歴タブ** — 記録したステップ・共通ポップアップの一覧、よく止まるステップのランキング、失敗時のスクリーンショットを確認できる。ここからレシピの削除や、失敗履歴・ログだけの消去もできる

各設定・ボタンの横にある丸い「**?**」をクリックすると、その項目の使い方が表示されます。

記録したレシピは `recipes/<名前>/` に保存されます（クリック位置を赤枠で示した確認用画像 `context_XX.png`、判定に使うテンプレート `step_XX.png` と変化しない部分だけを示すマスク `mask_XX.png`、再生ログ `playback_*.log`、失敗時のスクリーンショット `error_*.png`（赤枠＝そのとき最も一致した位置、緑十字＝記録上のタップ位置、黄バツ＝実際にタップした位置を書き込み済み）も一緒に残ります）。

## 調整のヒント

- **ボタンを検出しない** … 各ステップのしきい値は記録時に自動算出されるため、再生の「一致しきい値の調整（全体）」を -0.05 → -0.10 のようにマイナス方向に動かす。逆に別の場所を誤検出する場合はプラス方向に。ログの「しきい値」「最高一致度」が目安（値域は -0.2〜+0.2、初期値0.0。なお、しきい値を持たない古い形式のレシピではこの値がそのまま一致しきい値として使われる）
- **似たボタンを取り違える** … 「切抜き幅／高さ」を大きくして、周囲の文字ごと含めると区別しやすい
- **待ち時間が長い手順でタイムアウト** … 「各ステップ最大待ち秒」を上げる
- **記録中に画面が進まない** … 「クリックを端末にも送る」が ON か確認。反応が遅いアプリは「送信後に画面更新するまで秒」を長めに
- **記録時に「動かない部分がほとんどありません」と警告が出る** … 切り抜いた範囲のほぼ全体が数フレームの間に変化していて、判定の手がかりにできる安定した画素が少ない状態（常時アニメーションしている領域など）。文字や模様が入った動かない部分が写るよう切り抜き範囲を広げるか、別の場所をクリックし直す
- **広告やお知らせ画面で止まってしまう** … そのボタンを「共通ポップアップとして記録」しておくと、以後は順番を問わず自動で閉じるようになる

## exe にする（初回ビルド／コード変更時）

```bash
pip install pyinstaller
build.bat
```

`dist/TapReplay/TapReplay.exe` が生成されます。`adb.exe` は同梱済みなので、`dist/TapReplay/` フォルダごと配布・実行すればそのまま動きます（フォルダの中身を分割せず、`_internal` フォルダも含めて丸ごと保ってください）。

ビルドに成功すると、デスクトップに `TapReplay.lnk` ショートカットが自動作成されます（リンク先・作業フォルダともに `dist/TapReplay/` を指すので、ショートカットから起動しても `recipes/` は正しい場所に作られます）。同名のショートカットは確認なしで上書きされます。ショートカット作成に失敗してもビルド自体は成功扱いになり、警告が表示されるだけです（`dist/TapReplay/TapReplay.exe` は変わらず使えます）。

対応バージョン（Python 3.11〜3.13）の Python が見つからない場合、`build.bat` はインストールの実行有無を必ず確認してから進めます（無言では何もインストールしません）。`py` ランチャー経由で使えるバージョンが既にあればそれを使うか尋ね、無ければ winget での Python 3.13 インストールを提案します。

コードを変更するたびに `build.bat` を手動実行するのが面倒な場合は、`watch_build.bat` を開いたままにしておくと `core.py` / `gui.py` の保存を検知して自動で再ビルドしてくれます（詳細はウィンドウ内のログを参照）。

## ファイル構成

| ファイル | 役割 |
|---|---|
| `gui.py` | 本体のソース（配布・実行は exe 経由。開発時のみ直接編集） |
| `core.py` | 端末接続・画面クリック記録・画像マッチング |
| `build.bat` | exe を作るビルドスクリプト |
| `create_shortcut.ps1` | ビルド成功後に `build.bat` から呼ばれる、デスクトップショートカット作成スクリプト |
| `watch_build.bat` / `watch_build.ps1` | ソース変更を検知して自動で exe を再ビルドする監視スクリプト |
| `TapReplay.spec` | PyInstaller のビルド設定 |
| `icon.ico` | exe のアイコン |
| `requirements.txt` | 依存ライブラリ |
| `THIRD_PARTY_LICENSES.txt` | 同梱している第三者コンポーネントのライセンス表示 |
| `recipes/` | 記録したレシピ（自動生成） |
